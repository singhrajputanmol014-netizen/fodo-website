# FODO v52 report: FODO Studio on the website (`/studio/`)

The owner asked to bring the FODO Studio desktop app (social media, studio, marketing) onto fodo.co.in so anyone can sign in
with their FODO account and use it, with two conditions: all processing power (clipping, editing, rendering) comes from the
user's own computer, never from FODO's servers, and the Studio must look exactly like the app.

## What the person gets
- **`/studio/`**: the FODO Studio app layout (same sidebar, cards, fonts, icons, Light / Dark / Auto) on desktop and phone
  (phone: top bar + slide-in menu). Workspace ▸ Social Studio opens it. Logged out: a login card that goes to the FODO login.
- **Home:** 7-day scheduled / posted, drafts to approve, inbox leads, followers, failures; "Up next" list.
- **Calendar:** month view per project, drag a scheduled post to another day (time stays), ideas shown on their day.
- **Publish:** media library (chunked upload, 4 MB parts), composer (accounts, title, caption, AI caption via Workers AI,
  next free slot / pick a time / post now / draft), filters, approve, post now, cancel, delete.
- **Inbox:** comments from connected accounts, tags (lead / question / complaint), AI reply suggestion, saved replies, reply
  (needs "Allow replies" permission on connect).
- **Clients:** projects (one per brand / client, colour, time zone, posting slots), connect Instagram / Facebook (Meta) and
  YouTube (Google), manual accounts, client approval links.
- **Content planner:** idea board with drag between stages, AI ideas.
- **Analytics & reports:** views / likes / comments, top videos, best-time heatmap, printable report and CSV (formula-safe).
- **Link in bio:** editor with live phone preview, public page `/l/<slug>` with click counter (`/l/<slug>/go/<key>`).
- **AI Clipping / Editor / Caption & Font Studio:** detect the FODO Studio app on this computer (`127.0.0.1:8777`) and open it;
  device keys let the app send finished clips to the cloud library (`/api/social/agent/*`). No clipping runs on FODO servers.

## How it works
- `functions/_lib/sstudio.js`: tables `ss_projects`, `ss_accounts`, `ss_follow`, `ss_media`, `ss_posts`, `ss_ideas`,
  `ss_comments`, `ss_replies`, `ss_links`, `ss_bio`, `ss_devices` (SETUPS module `sstudio`, `SCHEMA_VERSION` 52.0).
  Tokens sealed with `GSC_ENC_KEY`. Media in R2 `MEDIA` when bound (500 MB per file, 10 GB per user), else KV (100 MB / 400 MB).
  Platforms fetch media through short-lived HMAC-signed URLs with Range support.
- Publishing is a resumable state machine (Instagram Reels by `video_url`, Facebook `/videos` by `file_url`, YouTube resumable
  upload) advanced by `sstudio.tick`, called from the hourly `/api/monitor/jobs`.
- `functions/api/social/[[path]].js`: session routes for every feature; writes need same-origin + JSON; raw part uploads need
  `x-fodo-upload: 1`. Public: signed media, approval page data / decision, agent routes (Bearer device key, stored hashed).
- Front end: `studio/index.html` (generated by `scripts/build_pages.py`, no inline script), `js/fodo-studio-theme.js`,
  `js/fodo-studio.js` (shell, provides `window.FODO_WS`, maps the shared view classes onto the app's components),
  `js/fodo-studio-ui2.js` and `css/fodo-studio.css` (copied from the app), `js/ws-social.js` (all views).
- `/studio/*` headers: noindex, no-store, strict app CSP. robots.txt disallows `/studio/`. connect-src allows
  `127.0.0.1:8777` / `localhost:8777` (app detection only).

## v52.1 and v52.2 (same day): the app finds itself, install for everyone, per-person control panel

- **v52.1:** the Studio's AI Clipping tab now finds the FODO Studio app on the visitor's own computer. The app's `/health` answers fodo.co.in only (CORS + `Access-Control-Allow-Private-Network`). The Open buttons stay hidden until the app is found (`[hidden]` fix). Steps text no longer promises a "Send to FODO" button that does not exist yet.
- **Get the app (`#social?tab=app`):**
  - Windows installer `downloads/FODO-Studio-Setup.exe` (NSIS, per-user, no admin), plus a `.zip` alternative.
  - Mac package `downloads/FODO-Studio-Mac.zip` (FODO Studio.app + "Install FODO Studio.command").
  - Phones: add `/studio/` to the home screen (`studio/manifest.webmanifest`, apple-mobile-web-app tags, icons in `assets/fodo-studio/`). Clipping needs a computer.
  - The card for the visitor's own device is shown first.
  - `downloads/app.json` holds the version, sizes and SHA-256. `/downloads/*` is noindex and no-cache; `.exe` and `.zip` are served as attachments; robots.txt disallows `/downloads/`.
- **Control panel (`#social?tab=control`, `GET /api/social/control`):** one person's own data. It shows:
  - Account, plan and storage bar.
  - Projects, connected platforms (and ones needing a reconnect), posts in the last 30 days, scheduled, failed, new comments, ideas, approval links, bio pages.
  - Their linked computers and recent activity.
  - "This computer": whether the app runs here, its power mode, and buttons that open the app and its own Control Panel (`127.0.0.1:8777/#panel`).
- **Installed app (built from the FODO Studio app repo, `tools/build_installer.py`):**
  - It is the "personal edition" (`edition.json`): the first account made on that PC becomes its owner, with the full Control Panel. Nobody else can sign in unless the owner invites them.
  - It ships no FODO data, secrets or storage; the build refuses to run if token-like strings are found.
  - **Power engine:** it reads the CPU, RAM and GPU (NVIDIA / Intel / AMD / Apple chip) and picks Maximum, Balanced or Saver. That sets the speech models, CPU threads, the export quality and the GPU encoder (NVENC, QSV, AMF, VideoToolbox). Saver runs below normal priority so the PC stays smooth. Owner choices win; Control Panel ▸ Power changes it.
- **Not verified on real hardware yet:**
  - Mac install: the scripts pass a syntax check, but no real Mac was available.
  - The NSIS installer has not been run on a Windows PC.
  - Neither is code-signed: Windows SmartScreen asks "More info ▸ Run anyway"; on a Mac, right-click ▸ Open.
- **Tests:** v52 100/100 (control panel isolation, downloads, manifest, new tabs). App: 202 passed (power tiers incl. Apple / AMD, personal edition, health CORS).

## v52.3: Mac audit (20-11-2026)

No Mac was available, so the audit used code review, checks against the vendors' current pages, the real Python wheels resolved for macOS, and a full install run in a Mac-like shell.

### Problems found and fixed
1. **Homebrew's `ffmpeg` no longer renders captions.**
   - Homebrew slimmed the formula in January 2026: no libass and no freetype. Every captioned export would have failed.
   - `ffmpeg-full` has them, but it is keg-only and has ready-made bottles only for Apple chips on macOS 15+.
   - Fix: a static FFmpeg build (github.com/vanloctech/ffmpeg-macos), native arm64 and x86_64. Inspected here: libass, freetype, fribidi and x264 are included; the arm64 build is ad-hoc signed; the minimum is macOS 15. The builds tested are pinned by sha256.
   - Setup verifies the `ass` filter and `libx264` after download and stops with a clear message if either is missing.
2. **Homebrew is unreliable on many Macs.** Homebrew 7 (Sep 2026) moved Intel Macs and macOS 14 to Tier 3 (no new bottles), so the setup would have compiled for hours. It also needed an admin password and Xcode tools.
   - Fix: no Homebrew. Python 3.12 comes from `uv` (portable, in the app folder, `--no-bin`); Deno and Ollama come from their official GitHub releases. No admin password is needed.
3. **Right-click > Open no longer works on macOS 15.** The old instructions told people to use it; macOS 15 needs System Settings ▸ Privacy & Security ▸ Open Anyway instead.
   - Fix: the main path is now a Terminal one-liner, `curl -fsSL https://www.fodo.co.in/downloads/mac-install.sh | bash`. Files fetched with curl are not quarantined, so Gatekeeper does not block them.
   - The zip stays as a fallback, with the correct macOS 15 steps.
4. **Python packages:** the wheels for arm64 and x86_64 were resolved against the real PyPI index. Two fixes:
   - `--prefer-binary`, so pip never builds a newer sdist from source (Windows got this too).
   - The opencv-python / opencv-contrib clash (scenedetect pulls the plain build) is now fixed on Mac, as on Windows.
5. **App code:**
   - The Control Panel monitor read `/proc` (Linux only) on macOS, and its first sample sat outside the try block, so the monitor thread died. It now uses Mach `host_statistics` and `vm_stat` on Mac and never stops on an unknown OS.
   - Health checks no longer warn "NVIDIA / NVENC / CUDA missing" on PCs without NVIDIA (Mac, AMD, Intel). They report the real graphics card, encoder and power plan.
   - The CUDA button is hidden without NVIDIA.
   - Messages no longer say "run setup.bat" on Mac.
   - The Ollama path is found on Mac.
   - Restart works on Mac and on installed Windows copies; before, it only worked with `run.bat`.

### Verified
- A Mac-like simulation (fake `sw_vers`, `sysctl`, `ditto`, `xattr` and `open`; real `uv`, Python 3.12 and pip) ran the full flow: one-liner → download → install → setup → launch.
- The server started, `/health` answered fodo.co.in with the power mode, and the personal edition asked for an owner.
- Re-install kept the user's data, macOS 14 was refused with a clear message, and nothing was written outside the app folder.
- shellcheck is clean. App tests: 205 passed, including 3 new Mac tests (Apple chip probe, vm_stat parser, health without NVIDIA).
