# FODO Website Builder — architecture (v28)

| Part | File |
|---|---|
| App (wizard, dashboard, visual editor) | `website-builder/index.html` (generated by `scripts/build_pages.py`) + `js/website-builder.js` + `css/website-builder.css` |
| API | `functions/api/sites/[[path]].js` → `functions/_lib/sites.js` |
| Renderer (one module everywhere) | `sites/lib/render.js` |
| Templates + license engine | `sites/lib/templates.js` |
| Live websites | separate Cloudflare Pages project, root `sites/` (`sites/functions/[[path]].js`, `sites/lib/serve.js`) |

## Data (D1, tenant-scoped)

| Table | Holds |
|---|---|
| `sites` | `id`, `tenant_id`, `owner_user_id`, `slug`, `status`, `doc` (draft), `rev`, `published` (snapshot) |
| `site_versions` | Every autosave older than 20 min, every publish, manual versions and restores |
| `site_domains` | Domain, TXT token, status, SSL |
| `site_forms` | Form submissions |
| `site_stats` | Per day / path / metric, from real beacon events only |
| `site_media` | Image metadata (bytes in KV) |
| `site_ai` | Every AI action |

## A website is data

`{theme, settings, pages:[{slug, title, seo, sections:[{type, props}]}]}`, rendered by `render.js`.

- There are 18 section types and no raw-HTML section.
- All text is escaped and URLs are filtered.
- Custom CSS is sanitised. Scripts are never stored.

This makes the visual editor, AI edits, export and publishing all work on the same document.

## Editor

- **Canvas:** a sandboxed iframe (`allow-scripts` only).
  - Click a section to see its properties.
  - Double-click text to edit it inline.
  - Drag & drop sections and pages; duplicate and delete them.
- **AI:**
  - Command bar (⌘K / Ctrl K): the AI returns ops for this one document, which can be undone.
  - AI rewrite on every text field.
- **Pages:**
  - Responsive preview (desktop / tablet / mobile).
  - Responsive check measures the real layout at 375px.
  - SEO panel, page passwords, hidden pages.
- **Safety nets:**
  - Undo/redo (Ctrl+Z / Ctrl+Shift+Z).
  - Autosave every 1.5 s with conflict detection (`rev`). A stale save gets a 409 with the newest version.
  - Local draft in localStorage for crash recovery.

## Publish

1. `checkSite()` runs. It blocks on any of these:
   - no home page
   - empty page
   - placeholder text (for example un-replaced reviews — the AI never writes reviews, numbers or people)
   - a broken internal link
2. It warns about:
   - missing H1, title or description
   - images without alt text
   - a missing notify email
3. The published snapshot is served by the sites project and by a sandboxed fallback at `/api/sites/view/<slug>/`.

## Quality bar and pain points

| Pain point | How FODO handles it |
|---|---|
| Too complicated | AI-first: wizard + command bar |
| Generic templates | AI personalisation |
| Mobile breaks | Mobile-first renderer + responsive check |
| Confusing domains | DNS assistant with real DNS checks |
| Fear of losing work | Autosave + versions + local draft |
| Lock-in | ZIP export of static HTML + `site.json` |
| Confusing SEO | Per-page SEO + checks |
| Bad AI websites | Publish checks + the owner approves |
